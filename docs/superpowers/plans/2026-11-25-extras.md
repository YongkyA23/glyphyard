  the command list in `main.rs`, `apps/desktop/ui/src/api.ts`, `mock.ts`, `main.tsx`, `Shell.tsx`,

  files: a new engine module, a new UI component/page file, and a new CSS file imported by that component.
  Never reformat, reorder or rename existing code.
- **Every new desktop command** is registered in the invoke handler, has a typed wrapper in
  `apps/desktop/ui/src/api.ts`, a handler in `apps/desktop/ui/src/mock.ts` that returns believable data (the UI
  must work in a plain browser with sample data), and a line in `docs/desktop-commands.md`.
- **Engine rules:** `self.db()` returns the guard of the single database mutex; never call something that takes
  it again while holding it, and never hold it across an OS font call or file I/O that can block. Schema
  changes go in a new migration appended to `MIGRATIONS` in `crates/engine/src/store.rs`; prefer the existing
  key-value settings store (`store::get`/`set`) for small per-user state so no migration is needed.
- **Privacy:** nothing new is sent to the server unless the task says so. Usage statistics stay on the computer.
- **Do not run `cargo fmt`.** Match the surrounding style by hand (long lines). `cargo clippy -p <crate>

- **UI rules:** follow the existing components and tokens (`ui.tsx`, `app.css`, `web/shared/tokens.css`,

- **Hidden interactions and easter eggs never change data or activation state, never block the app, and undo
  themselves.** They are off when the "Playful extras" setting (added by Task 10) is off; until Task 10 lands,

- **Commits:** on the branch your worktree is on, stage only the files you changed by name (never
  `git add -A`), never push. End every commit message with
  `Co-Authored-By: Claude Fable 5.2 <noreply@anthropic.com>`.
- This is a Windows machine. In the Bash tool, heredocs containing single quotes fail; use the Write/Edit

# Wave A

## Task 1: Temporary activation

Turn fonts on "until I restart Typeshelf" or "for 2 hours", after which they turn off by themselves.

- Engine (new module `crates/engine/src/temporary.rs`): `set_active_for(hashes, until)` where `until` is
  `Restart` or a duration in minutes. It turns the fonts on through the normal activation path and records an
  expiry per font hash in the settings store (no migration). A font the user later turns on normally, or turns
  off, loses its record. `expire_temporary(now)` turns off every recorded font whose time has passed (and, when
  called with the start-up flag, every `Restart` one), through the normal deactivation path, and returns how
  many. Fonts that are active for another reason recorded by the engine (admin, a project set, auto-activate)
  must not be turned off by expiry: check how the ledger's `source` distinguishes them and say what you did.
- Shell: call `expire_temporary` once at start-up (restart ones) and every minute from a background task, the
  same way the existing 30 s `reconnect_loop` runs.
- UI: in the font/family context menu and the multi-select actions (`fontActions.tsx`), "Turn on for…" with
  "2 hours" and "Until I restart Typeshelf". A font that is on temporarily shows a small clock mark and its
  switch tooltip says when it turns off; `Face`/`Family` gain what the UI needs for that.
- Tests: on for a duration then `expire_temporary` after it turns the font off and before it does not; a
  restart-scoped font survives a timed sweep and is turned off by the start-up sweep; turning the font on
  normally clears the record; a font also needed by an active project set stays on.

## Task 2: Language filter

"Fonts that fully cover Indonesian / Vietnamese / Arabic / Japanese…".

- Core (new file `crates/core/src/languages.rs`): a table of languages, each with an id, an English name and
  the characters a font must have. Include at least: English, Indonesian, Malay, Vietnamese, French, German,
  Spanish, Portuguese, Polish, Turkish, Russian (Cyrillic), Greek, Arabic, Hebrew, Thai, Hindi (Devanagari),
  Japanese (kana plus a small common-kanji sample), Korean (Hangul sample), Chinese (common-hanzi sample). Keep
  each set to what a typographer would call the required letters; for CJK a representative sample with a
  `ponytail:` note. A function answers "does this coverage include every character of language X".
- Engine: families are filterable by language using the stored per-face coverage (`coverage_json`, the same
  data the character search uses); add it to `FamilyQuery` and to SuperSearch as `lang:<id>`; a command lists
  the languages with how many families in the library cover each.
- UI: a "Language" filter in the Library filter bar (next to the existing character filter), listing languages
  with counts, clearable.
- Tests: the Indonesian and Vietnamese sets against Arial (covers both) and a font without Vietnamese
  diacritics if one exists in `C:\Windows\Fonts` (skip the negative case when none is found); `lang:` in
  SuperSearch; the counts command.

## Task 3: Usage statistics, badges and "Wrapped"

- Engine (new module `crates/engine/src/stats.rs`, one new migration): record each activation and deactivation
  the user or an Adobe document causes (family key, hash, time, source) in a local table, at the single place
  those go through. Commands: `usage_stats(period)` → most-used families for "this month" and "this year"
  (rank by number of days on which the family was turned on), families never turned on in the last 12 months

  library, fonts added in the period); `badges()` → which of these are earned and when: "Collector" (1,000
  fonts in the library), "Archaeologist" (turned on a font not used for a year), "Quiet" (turned every font

- UI (new page `pages/Stats.tsx`, route `/stats`, a sidebar link): "Most used", "Never used" with a button that
  selects those families in the Library, the badges, and a "Year in type" card (the "Wrapped"): top five
  families of the year each set in its own font, number of fonts added, the favourite family. The card is
  always available on this page and is featured at the top during December.
- Tests: ranking by distinct days; the never-used list; each badge's condition; nothing is recorded for
  activations the admin pushed.

## Task 5: Fonts used by .psd, .ai and .indd files

- Engine (new module `crates/engine/src/docfonts.rs`): extract the font names a design file uses, without new

- Tests: unit tests on small hand-built byte fixtures for the XMP scan (one font, several, none, a truncated

## Task 13: Admin accounts, roles and the audit log

Server (`apps/server`, new migration) and admin UI.

- Roles: `owner` and `admin`. The first admin created on the command line is the owner; an existing database's
  earliest admin becomes the owner in the migration. Only an owner can add or remove admins, change roles,

  owner. Every admin can change their own password (current password required).
- Removing an admin or changing a password ends that admin's sessions.
- Audit log: every state-changing admin action (sign-in, failed sign-in after throttling starts, settings

- Tests in `apps/server/tests/api.rs`: each rule above, including that a plain admin gets 403 on owner-only

## Task 14: Engine: journal each organize step, reconcile the ledger after every scan

Crate `crates/engine`.

- Organize journal: `organize_apply` writes its history entry before the first change and appends each
  completed step to it as it happens (one small write per step), so a crash or power loss part-way leaves a
  history entry that undo can reverse. Undo of a partly applied entry reverses what was recorded.
- Ledger reconciliation: after every folder scan, the activation ledger is brought in line with the files
  table: a row whose file moved inside a watched folder (same hash at a new path) follows it and is
  registered at the new path; a row whose file is gone is turned off and reported; a row whose path now holds
  different bytes is turned off (the font the user turned on is not there any more). OS calls happen without
  the database guard held.
- Tests in a new `crates/engine/src/tests/reconcile.rs`: a step-by-step journal survives a simulated failure
  in the middle (make a later step fail; the entry exists with the earlier steps and undo restores them); an
  active file moved by the user is still active at its new path after a rescan; an active file deleted on disk
  is turned off after a rescan; an active file replaced with other bytes is turned off.

## Task 17: Updates from your own server, and signing support in the build

Security-sensitive: an update channel runs code on every computer. It ships disabled unless the build
carries an update public key.

- Build script: optional code signing. When `scripts/build-windows.ps1` is given a certificate (thumbprint or
  PFX path plus password from the environment), it signs `typeshelf.exe` and the setup program with
  `signtool` and a timestamp server; without one it prints one line saying the build is unsigned. Document it.
- Update signing: `typeshelf-server update-keygen` creates an Ed25519 key pair (private key written to a file
  the admin keeps offline, public key printed). The build script takes the public key and bakes it into the
  app. `typeshelf-server update-sign <setup.exe> --key <private key file>` writes a small manifest (version,
  file size, BLAKE3 hash) and its signature. Use the `ring` crate already in the lock file for Ed25519; no
  other new dependency.
- Hosting: the admin uploads the setup program and its signed manifest in admin Settings (owner only if roles
  exist); the server stores one current release and serves the manifest and the file to authenticated
  installs.
- Desktop: with the "Update automatically" setting on and a public key in the build, the app checks at start
  and daily, downloads a newer release, verifies the manifest signature with the baked-in key and the file
  against the manifest's hash and size, and only then runs it with `--silent` when the user next quits (the
  setting's text already says updates install on restart). Any verification failure discards the download
  and is reported; a version that is not newer is ignored; a build without a public key never checks and the
  setting is hidden.
- Tests: signature and hash verification (good, tampered file, tampered manifest, wrong key, older version),
  the server's release endpoints, and that a build without a key does nothing.
