# Extras: ten features, five hidden interactions, nine easter eggs

Source: the idea list the user approved on 2026-11-25 ("add all of it"). Ten tasks in two waves; the tasks of
a wave are built in parallel in separate git worktrees and integrated onto `feat/extras`.

Branch: `feat/extras` (local only, never pushed by this plan).

## Global Constraints

- **Build the smallest version that does what the task says.** No options, settings or abstractions the task
  does not ask for. No new dependencies (Rust crates or npm packages); a crate already used elsewhere in the
  workspace still counts as new for a crate that does not depend on it today.
- **Test first for logic.** Engine, core, server and sync logic gets a failing test first (engine tests go in a
  NEW file `crates/engine/src/tests/<task>.rs`, declared with one `mod <task>;` line at the end of
  `crates/engine/src/tests.rs`; server tests in `apps/server/tests/api.rs`). The UIs have no test runner and
  must not gain one: verify UI with `bunx tsc --noEmit -p tsconfig.app.json` and `bunx oxlint` in that UI's
  folder (no type errors, no new warnings; run `bun install --frozen-lockfile` there first).
- **Other agents edit the same shared files at the same time** (`apps/desktop/src-tauri/src/commands.rs` and
  the command list in `main.rs`, `apps/desktop/ui/src/api.ts`, `mock.ts`, `main.tsx`, `Shell.tsx`,
  `pages/Library.tsx`, `app.css`, `crates/engine/src/types.rs`, `lib.rs`, `docs/desktop-commands.md`). Keep
  your edits to those files small and additive, next to the related existing code. Put everything else in NEW
  files: a new engine module, a new UI component/page file, and a new CSS file imported by that component.
  Never reformat, reorder or rename existing code.
- **Every new desktop command** is registered in the invoke handler, has a typed wrapper in
  `apps/desktop/ui/src/api.ts`, a handler in `apps/desktop/ui/src/mock.ts` that returns believable data (the UI
  must work in a plain browser with sample data), and a line in `docs/desktop-commands.md`.
- **Engine rules:** `self.db()` returns the guard of the single database mutex; never call something that takes
  it again while holding it, and never hold it across an OS font call or file I/O that can block. Schema
  changes go in a new migration appended to `MIGRATIONS` in `crates/engine/src/store.rs`; prefer the existing
  key-value settings store (`store::get`/`set`) for small per-user state so no migration is needed.
- **Privacy:** nothing new is sent to the server unless the task says so. Usage statistics stay on the computer.
- **Do not run `cargo fmt`.** Match the surrounding style by hand (long lines). `cargo clippy -p <crate>
  --all-targets -- -D warnings` stays clean for every crate touched and its tests pass.
- **UI rules:** follow the existing components and tokens (`ui.tsx`, `app.css`, `web/shared/tokens.css`,
  `motion.ts`); every control is reachable by keyboard and has an accessible name; animation respects
  `prefers-reduced-motion`; text is plain English like the rest of the app, says what happened and what the
  person can do. The UI is English; where a task lists Indonesian words they are accepted as input as well.
- **Hidden interactions and easter eggs never change data or activation state, never block the app, and undo
  themselves.** They are off when the "Playful extras" setting (added by Task 10) is off; until Task 10 lands,
  a task that needs the flag reads `settings.playful` and treats a missing value as on.
- **Commits:** on the branch your worktree is on, stage only the files you changed by name (never
  `git add -A`), never push. End every commit message with
  `Co-Authored-By: Claude Fable 5.2 <noreply@anthropic.com>`.
- This is a Windows machine. In the Bash tool, heredocs containing single quotes fail; use the Write/Edit
  tools. Prefix cargo commands with `CARGO_TARGET_DIR=C:/Users/lenovo/Documents/GitHub/typeshelf/target` so
  dependencies are not rebuilt ("Blocking waiting for file lock" means another agent is building: wait).
  `cargo check -p typeshelf-desktop` needs `apps/desktop/ui/dist` and `plugins/dist` to exist; create them
  empty if missing (they are git-ignored; do not commit them).
- `// ponytail:` comments mark a deliberate shortcut: name the ceiling and the upgrade path.

# Wave A

## Task 1: Temporary activation

Turn fonts on "until I restart Typeshelf" or "for 2 hours", after which they turn off by themselves.

- Engine (new module `crates/engine/src/temporary.rs`): `set_active_for(hashes, until)` where `until` is
  `Restart` or a duration in minutes. It turns the fonts on through the normal activation path and records an
  expiry per font hash in the settings store (no migration). A font the user later turns on normally, or turns
  off, loses its record. `expire_temporary(now)` turns off every recorded font whose time has passed (and, when
  called with the start-up flag, every `Restart` one), through the normal deactivation path, and returns how
  many. Fonts that are active for another reason recorded by the engine (admin, a project set, auto-activate)
  must not be turned off by expiry: check how the ledger's `source` distinguishes them and say what you did.
- Shell: call `expire_temporary` once at start-up (restart ones) and every minute from a background task, the
  same way the existing 30 s `reconnect_loop` runs.
- UI: in the font/family context menu and the multi-select actions (`fontActions.tsx`), "Turn on for…" with
  "2 hours" and "Until I restart Typeshelf". A font that is on temporarily shows a small clock mark and its
  switch tooltip says when it turns off; `Face`/`Family` gain what the UI needs for that.
- Tests: on for a duration then `expire_temporary` after it turns the font off and before it does not; a
  restart-scoped font survives a timed sweep and is turned off by the start-up sweep; turning the font on
  normally clears the record; a font also needed by an active project set stays on.

## Task 2: Language filter

"Fonts that fully cover Indonesian / Vietnamese / Arabic / Japanese…".

- Core (new file `crates/core/src/languages.rs`): a table of languages, each with an id, an English name and
  the characters a font must have. Include at least: English, Indonesian, Malay, Vietnamese, French, German,
  Spanish, Portuguese, Polish, Turkish, Russian (Cyrillic), Greek, Arabic, Hebrew, Thai, Hindi (Devanagari),
  Japanese (kana plus a small common-kanji sample), Korean (Hangul sample), Chinese (common-hanzi sample). Keep
  each set to what a typographer would call the required letters; for CJK a representative sample with a
  `ponytail:` note. A function answers "does this coverage include every character of language X".
- Engine: families are filterable by language using the stored per-face coverage (`coverage_json`, the same
  data the character search uses); add it to `FamilyQuery` and to SuperSearch as `lang:<id>`; a command lists
  the languages with how many families in the library cover each.
- UI: a "Language" filter in the Library filter bar (next to the existing character filter), listing languages
  with counts, clearable.
- Tests: the Indonesian and Vietnamese sets against Arial (covers both) and a font without Vietnamese
  diacritics if one exists in `C:\Windows\Fonts` (skip the negative case when none is found); `lang:` in
  SuperSearch; the counts command.

## Task 3: Usage statistics, badges and "Wrapped"

- Engine (new module `crates/engine/src/stats.rs`, one new migration): record each activation and deactivation
  the user or an Adobe document causes (family key, hash, time, source) in a local table, at the single place
  those go through. Commands: `usage_stats(period)` → most-used families for "this month" and "this year"
  (rank by number of days on which the family was turned on), families never turned on in the last 12 months
  (only for libraries older than 30 days; before that the list is empty with a reason), totals (fonts in
  library, fonts added in the period); `badges()` → which of these are earned and when: "Collector" (1,000
  fonts in the library), "Archaeologist" (turned on a font not used for a year), "Quiet" (turned every font
  off at once, at least 10). A newly earned badge emits a UI event the shell shows as a toast.
- UI (new page `pages/Stats.tsx`, route `/stats`, a sidebar link): "Most used", "Never used" with a button that
  selects those families in the Library, the badges, and a "Year in type" card (the "Wrapped"): top five
  families of the year each set in its own font, number of fonts added, the favourite family. The card is
  always available on this page and is featured at the top during December.
- Tests: ranking by distinct days; the never-used list; each badge's condition; nothing is recorded for
  activations the admin pushed.

## Task 4: Ask the admin for a font

- Protocol and desktop: a designer can send "I need this font" (font name, optional note) from a dialog
  reachable from the Library toolbar and from each missing row on the document-fonts page (`PdfFonts.tsx`);
  it travels as a new event through the existing offline outbox. The dialog says it goes to their admin.
- Server (new migration): requests are stored (who, font name, note, when, state open/done). Admin API: list
  requests (paged, filter open/done), mark done / reopen. The Overview "attention" block gains an
  open-requests count. An old server that receives the new event must not reject the whole batch: check how
  unknown event kinds are handled today and say what happens with an old server (the desktop now drops only
  the rejected event).
- Admin UI (new page `pages/Requests.tsx`, sidebar link with the open count): who asked, for what, when, the
  note, "Mark done" and a link to that user. No delivery automation: the admin uploads and delivers through the
  existing Library page.
- Tests: server API tests for receiving a request event, listing, marking done, the overview count; an engine
  or sync test that the event round-trips through the protocol type.

## Task 5: Fonts used by .psd, .ai and .indd files

- Engine (new module `crates/engine/src/docfonts.rs`): extract the font names a design file uses, without new
  dependencies. `.ai` and `.indd` carry an XMP packet listing fonts (`xmpTPg:Fonts` with `stFnt:fontName`
  entries): scan the file for it. `.ai` files saved PDF-compatible can also go through the existing PDF path.
  `.psd`: scan the text-engine data for font names (PostScript names appear as UTF-16 strings in the
  `/FontSet` array of each type layer). Read files in bounded chunks, never load a multi-gigabyte file whole,
  and cap the work with a `ponytail:` note. Return the same shape the PDF command returns (name, whether the
  library has it, whether it is on) and reuse its matching, so the page can show one list.
- Command and UI: the existing page (`pages/PdfFonts.tsx`) accepts `.pdf`, `.psd`, `.ai`, `.indd` by picker and
  drop, is titled for documents in general, and drops the "Coming later" line. Results say plainly when a file
  type gave no font list ("This file doesn't list its fonts").
- Tests: unit tests on small hand-built byte fixtures for the XMP scan (one font, several, none, a truncated
  packet) and the PSD scan (a `/FontSet` with UTF-16 names); the command returns "not in library" and "in
  library" rows correctly for a fixture naming Arial.

# Wave B

## Task 6: Family page: copy a glyph as SVG, anatomy overlay, poster mode

- Engine/core: `glyph_svg(hash, face index, codepoint)` returns a standalone SVG (viewBox from the font's
  units, one `<path>`) built with the font library already in use (`skrifa` outline drawing). Test: the SVG for
  "A" in Arial has a non-empty path and a sensible viewBox; a missing glyph is an error.
- UI (`pages/Family.tsx` plus new component files): right-click (and a keyboard-reachable button on) a glyph →
  "Copy as SVG" puts the SVG text on the clipboard and confirms with a toast. Holding **Alt** while pointing at
  (or focusing) a glyph in the glyph grid shows its anatomy lines: baseline, x-height, cap height, ascender,
  descender, labelled, from the face's stored metrics (find what `metrics_json` holds; draw only the lines the
  data has). Holding **Space** on the family page (not while typing in a field) shows a full-window "poster" of
  the family name and sample text in that font; releasing Space, or Escape, closes it.

## Task 7: Playground: compare, pairing suggestions, variable presets, drag to pair

- Compare: a "Compare" toggle in the Playground overlays font B on font A for the same text (B semi-transparent
  in an accent colour), sizes matched by x-height when both faces have that metric, otherwise by font size.
- Pairing suggestions: engine command `pairing_suggestions(family key)` → up to 8 families from the library
  that contrast with it (a different category, e.g. serif with sans, and close x-height ratio), using the same
  stored metrics the "Similar" list uses; the Playground shows them for font A as one-click choices for B.
  Test the ranking on the fixture fonts.
- Variable presets: for a variable font, the current axis settings can be saved under a name, listed, applied
  and deleted (settings store, per family key).
- Drag to pair: dragging one family row onto another in the Library opens the Playground with A = the target
  and B = the dragged one. It must not interfere with the existing drag of fonts onto collections.

## Task 8: Dark theme and a changeable quick-activate shortcut

- Theme: `Settings.theme` (`system` | `light` | `dark`) already exists in the type and is stored. Make it
  work: a dark palette for every token in `web/shared/tokens.css` and any colour hard-coded in
  `apps/desktop/ui/src/app.css` (move those to tokens), applied through a `data-theme` attribute on the root
  with `system` following `prefers-color-scheme`; a three-way control in Settings; both windows (main and
  quick) follow it; text contrast at least WCAG AA in both themes; font previews stay legible.
- Shortcut: the Settings page shows the quick-activate shortcut as text today. Make it a control: press
  "Change", press the new combination, it is validated (needs a modifier, not a reserved combination), saved
  through the existing `update_settings` path, and registered by the shell (the backend already supports
  changing it: check `commands.rs`); a failure to register is shown and the old shortcut kept.

## Task 9: Preview interactions and sample-text tokens

- In the Library and on the family page: **Ctrl + scroll** over a preview changes the preview size (within the
  existing size range; the page does not zoom or scroll); **Shift + scroll** over a variable font's preview
  changes its weight along the `wght` axis for that preview only (reset on leaving the row).
- Sample-text tokens: in the sample text, `:time` or `:jam` shows the current time (updating each minute),
  `:date` or `:tanggal` today's date in the system locale, `:name` or `:nama` the user's name from the app
  state. Unknown `:words` are left alone. One small pure function does the replacement.
- Breathing: when the app has had no pointer or key input for 3 minutes, variable-font previews on screen
  slowly move along their weight axis and back; any input stops it and restores the weights. Off under
  `prefers-reduced-motion` and when "Playful extras" is off.

## Task 10: Easter eggs and the "Playful extras" setting

All in new files (`apps/desktop/ui/src/extras/…`) with minimal hooks in `Shell.tsx`, `pages/Library.tsx` and
`pages/Settings.tsx`. Add `playful: boolean` (default true) to the settings (engine `AppSettings`, the type in
`api.ts`, the mock) with a "Playful extras" switch in Settings; when off none of these run.

1. Searching the library for exactly "comic sans" sets the whole interface in Comic Sans MS for 5 seconds;
   "papyrus" does the same with Papyrus (fall back to a fantasy stack when the font is not installed).
2. The Konami code (↑ ↑ ↓ ↓ ← → ← → B A, outside text fields) sets all text in Wingdings for 5 seconds.
3. Clicking a missing-glyph box (the "tofu" shown where a font lacks a character on the glyph and preview
   surfaces) three times "fries" it with a short animation.
4. When the sample text is "the quick brown fox" (start of the English pangram) or starts with the Indonesian
   pangram "Muharjo seorang xenofobia", a small fox runs once across the bottom of the window (inline SVG).
5. Clicking the app logo five times quickly opens a "font roulette": three reels spin and stop on one random
   family from the library, shown in its own font with "Open" and "Spin again".
6. A hidden games entry on the Settings › About area (revealed by clicking the version number three times):
   "Kern it" (five letters of a word in a library font start badly spaced; drag them; the score compares your
   spacing with the font's own, measured from the browser's natural layout of the word) and "Name that font"
   (a word set in a random library font, four family names to choose from, ten rounds).

Each effect restores the interface exactly and can be dismissed with Escape. Tests are not possible without a
runner: keep each piece small, and describe in the report how each was checked by reading.
